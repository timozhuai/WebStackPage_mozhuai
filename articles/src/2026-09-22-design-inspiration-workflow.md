设计师的收藏夹通常是个黑洞：一周存下几百张图，真到了要出方案的那天，翻十分钟翻不到能用的那一张，最后又回到从零开始想。

问题往往不在"看得不够多"，而在**采集、归档、复用这三件事被混成了一件**。这篇把它们拆开，按每一层实际要解决的问题来选工具。

## 第一层：先分清你缺的是"看"还是"找"

同样是"灵感站"，三类站点的产出物完全不同，用错了场合就是浪费。

- **作品展示型**：Dribbble（[dribbble.com](https://dribbble.com)）、Behance（[behance.net](https://www.behance.net)）。看的是风格倾向和视觉语言，适合定调性。要提醒的是，这两类平台上很多是概念稿，未必落地过，交互与内容填充的问题在里面看不到。
- **真实成品型**：Awwwards（[awwwards.com](https://www.awwwards.com)）、Land-book（[land-book.com](https://land-book.com)）、SiteInspire（[siteinspire.com](https://www.siteinspire.com)）、CSS Design Awards、The FWA。看的是真上线、真跑过流量的页面，能直接观察版式节奏、导航结构、动效分寸。站内[「网页灵感」分类](https://dh.mozhuai.site/#%E7%BD%91%E9%A1%B5%E7%81%B5%E6%84%9F)已经收了其中一批，从那里进比记网址省事。
- **产品截图型**：Mobbin（[mobbin.com](https://mobbin.com)）、Pttrns（[pttrns.com](https://www.pttrns.com)）、Collect UI（[collectui.com](http://collectui.com)）。这一类最被低估——它给的是真实 App 与网站的界面和流程截图，做需求评审、写交互说明、跟产品对齐"这个状态该长什么样"的时候，比任何概念稿都管用。Mobbin 覆盖 iOS、Android 与 Web，以订阅制为主；Pttrns、Collect UI 更偏按 UI 模式分类的免费截图合集，站内[「界面灵感」分类](https://dh.mozhuai.site/#%E7%95%8C%E9%9D%A2%E7%81%B5%E6%84%9F)里就有。

一句话选法：**定风格去看作品展示站，验证可行性去看成品站，写交付文档去看产品截图库。**

## 第二层：采集工具，按"以图为主"还是"以链接为主"分

存的时候最容易犯的错，是拿一个工具硬扛所有类型。按收藏对象的形态分两类会舒服很多。

**以图片为单位**：

- [Savee](https://savee.it)（savee.it）：面向设计师的图片收藏与灵感板，可以关注别人的收藏、按主题往下翻，社区氛围比通用图片站更贴设计。
- [Cosmos](https://www.cosmos.so)（cosmos.so）：强调视觉发现，收藏后会往相似方向推，适合在一个调性上持续挖深，而不是横向铺量。
- [Are.na](https://www.are.na)（are.na）：以「频道（Channel）」组织「块（Block）」，块可以是图片、链接、文字、文件。它比其他收藏工具更像**做研究**，一个频道就是一个论点，可以私有、公开或协作。免费额度与付费方案以官网当前说明为准。

**以链接为单位**：

- [Raindrop.io](https://raindrop.io)（raindrop.io）：跨平台书签管理，收藏夹加标签，支持全文检索和预览图，浏览器扩展到手机端都能同步。适合存"以后要再看一遍"的文章、组件库、规范文档。
- [Muzli](https://muz.li)（muz.li）：把设计资讯聚合成新标签页，属于"不主动找也会撞见"的被动采集，对付选题枯竭比较有效。

两条补充经验：一是**在同一台机器上尽量只用一个图片收藏工具**，工具一多，标签体系必然分裂；二是采集时顺手写一句"为什么存它"（一行就够），三个月后这句备注比图片本身值钱得多。

## 第三层：归档与参考板，本地化那部分不能省

云端收藏解决"不丢"，不解决"翻得动"。数量过千之后，本地库反而更快。

- [Eagle](https://en.eagle.cool)（en.eagle.cool）：桌面端本地素材管理，按颜色、格式、尺寸、标签筛选，配浏览器插件可以直接把网页上的图拖进库里。适合长期积累的大体量素材库，尤其做电商、平面、运营图这类需要"按色系找图"的场景。
- [PureRef](https://www.pureref.com)（pureref.com）：极轻量的参考画布，把图拖进去自由排布、缩放，窗口可以锁在最上层。项目期间把它摆在副屏，比在文件夹里来回点开高效得多。它提供 Windows、macOS、Linux 版本，具体授权与付费方式请以官网为准。
- [Hoverstat.es](https://hoverstat.es)：手选的小众与实验性网站合集，做交互动效选题时是一处不错的补充。

| 想存的东西 | 更合适的工具 | 原因 |
| --- | --- | --- |
| 零散视觉参考、风格碎片 | Savee / Cosmos | 采集快，推荐能延续调性 |
| 一个主题的长期研究 | Are.na | 频道 + 描述文本，本身就是论点 |
| 文章、文档、组件库链接 | Raindrop.io | 全文检索，链接管理更顺手 |
| 大体量本地素材 | Eagle | 本地、可按颜色与标签筛 |
| 项目期间的临时参考堆 | PureRef | 不用整理，摆在旁边就行 |

## 让灵感真正用得上：一条可以照做的流程

工具只是容器，真正决定复用率的是一条固定动作：

1. **采集时就打标签**，标签只用三类：项目名、模块（导航/表单/空状态）、调性（克制/活泼/科技感）。三类之外不再加，否则标签本身就成了负担。
2. **每周花十分钟做一次降噪**，把存下来但从没点开过的删掉。收藏夹的噪音比数量更致命。
3. **复用的时候问"为什么"**，而不是"像不像"。真正要抄的是版式层级、留白节奏、信息密度这类可迁移的东西；照搬视觉，换个内容就塌。
4. **把参考转成可执行结论**。看到一张喜欢的卡片，就在备忘里写清"阴影两层、圆角 12、标题与正文对比 1.5 倍"，这样它才进得了设计稿，而规范层面的取用方法可以参考之前整理的 [[public-design-systems|公开设计系统清单]]。

> [!tip] 一条版权提醒
> 收藏不等于可用。Dribbble、Behance 上的作品著作权归原作者，Mobbin 这类截图库的服务条款也限制二次分发。参考可以，直接搬进交付物之前请看平台条款与原作者说明，涉及字体、图库、图标时更要核对授权——这部分流程在 [[free-stock-photos|免费商用图库怎么选]] 和 [[open-source-icon-libraries|6 套开源图标库的规格与授权]] 里写过。

最后一句实话：灵感工具的价值不在你收藏了多少，而在它能不能让"下次做方案"少花二十分钟。如果还没有固定入口，本站导航的「灵感采集」板块已经按[发现产品](https://dh.mozhuai.site/#%E5%8F%91%E7%8E%B0%E4%BA%A7%E5%93%81)、[界面灵感](https://dh.mozhuai.site/#%E7%95%8C%E9%9D%A2%E7%81%B5%E6%84%9F)、[网页灵感](https://dh.mozhuai.site/#%E7%BD%91%E9%A1%B5%E7%81%B5%E6%84%9F)分好了组，先把入口固定下来，再慢慢补自己的标签体系。
